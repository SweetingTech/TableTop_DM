# TableTop DM 1.0 Known Limitations

Date: 2026-05-19

These items are not blockers for the local 1.0 release candidate, but they
should be visible before a GA tag.

## Local Identity

The 1.0 identity model is a local-desktop principal and join-code flow, not a
hosted OAuth/SSO system. It is suitable for the local Docker app and LAN-style
play, not public internet deployment.

## Route Module Granularity

`app.py` is now a small entrypoint and routes are centralized behind a Flask
blueprint in `services/api/application.py`. A deeper per-domain route-module
split is deferred to post-1.0 because public URLs and auth behavior are already
stable.

## Frontend Module Granularity

Game Console and Control Plane load through ES module entrypoints, but the
legacy runtime is still preserved behind compatibility facades. Removing inline
template handlers and splitting every manager into separate files is post-1.0
maintainability work.

## RAG With Local Providers

Local providers no longer silently use OpenAI embeddings. LM Studio/Ollama RAG
requires a reachable embedding-capable model. Without one, RAG upload/query
returns a clean setup error.

## AI Model Reliability

Small local chat models may fail structured Session Intel extraction even after
the correction retry. The extractor fails open and records skip reasons; it does
not auto-commit uncertain lore.

## Packaging Verification

The packaging script creates the release zip and checksums. A final clean
Windows VM unzip-and-run pass is still recommended immediately before uploading
the GA artifact.
