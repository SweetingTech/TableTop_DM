# TableTop DM 1.0 Security Matrix

Status: release-gate security and visibility policy. This is not a threat model for hosted public service operation; 1.0 targets local play with meaningful principal separation.

## Security Principles

- No principal context, no protected campaign/session data.
- No campaign membership, no campaign data.
- No session membership, no session runtime state.
- No DM role, no DM-only state.
- Query params may narrow requested visibility, never widen it.
- WebSocket delivery and REST snapshots must agree on audience.
- Save/load must preserve visibility and principal identity semantics.

## Principal Classes

| Principal | 1.0 access |
|---|---|
| Anonymous | Health, static pages/assets, documented public help only. No campaign/session state. |
| DM / AI_DM | Campaign management, DM packet, story-state DM fields, all visible scopes for owned campaign. |
| Player | Own player state, controlled entities, visible ledger/events/continuity, allowed actions. |
| Observer / God operator | Explicitly declared campaign-member views only; no accidental DM-only access. |
| System | Internal service operations only; not a browser identity. |

## Visibility Matrix

| Data class | Player access | DM access | Enforcement point |
|---|---|---|---|
| Ledger rows | `principal_id = ANY(visible_to)` | included when DM is in `visible_to` or DM route resolves scope | RLS/tests plus player-state query |
| Realtime events | public/party/principal/spatial only if audience resolves | DM room receives all scoped events | `services/realtime` |
| `player_state` | principal-scoped runtime projection | own or simulated player view | `services/player_state` |
| Recaps | party/principal/public scope only | DM scope | `services/session_intel/recap.py` |
| Continuity | no `dm_only`; principal rows only if `patch.visible_to` includes caller | full DM scope | `services/session_intel/continuity.py` |
| RAG chunks | purpose filter plus metadata visibility | DM retrieval can include DM-only | `services/rag/filters.py` |
| Story State | no `dm_notes` or private notes | full board | route/player-state serializers |
| Entity sheets | player gets public and own private sheet only | full as needed | player-state serializers and future route matrix |

## 1.0 Blockers

Any of these blocks 1.0:

- Anonymous or non-member API can read campaign/session runtime data.
- Player can pass another `principal_id` or `as_principal_id` to widen state.
- Player receives DM-only continuity, recap, RAG, story-state, ledger, or socket data.
- Snapshot includes data that equivalent WebSocket delivery would not deliver.
- Save/load changes principal ownership or widens visibility.
- DM route can be called by a player without explicit rejection.
