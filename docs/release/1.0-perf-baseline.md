# TableTop DM 1.0 Performance Baseline

Date: 2026-05-19

Scope: local demo campaign smoke budgets. These are regression guards, not
enterprise-scale benchmarks.

## Budgets

| Surface | Budget | Automated coverage |
| --- | ---: | --- |
| `GET /api/sessions/<id>/player_state` | < 300 ms | `tests/integration/test_v1_perf_smoke.py` |
| WebSocket event fanout | < 150 ms | `tests/integration/test_v1_perf_smoke.py` |
| `/game` first usable render | < 2 s after ready app | E2E smoke timing/manual QA |
| RAG query | < 1 s for demo docs or clean setup error | `tests/integration/test_v1_perf_smoke.py` |
| Save export/import | < 5 s for demo campaign | `tests/integration/test_v1_perf_smoke.py`, save/load torture suite |
| Startup readiness | documented repeatable local path | `scripts/verify_boot.ps1 -Mode docker` |

## Current Baseline Procedure

Run:

```powershell
pytest tests\integration\test_v1_perf_smoke.py -q
.\scripts\verify_boot.ps1 -Mode docker
pytest tests\e2e\test_player_state_boot.py -q
```

The integration smoke asserts hard budgets for player state, WebSocket fanout,
RAG query response behavior, and save export. HTTP endpoints are sampled three
times and checked against the best steady-state local sample so a one-time
Python/import/cache warm-up does not fail the running-session budget. Browser
first-usable render is covered by E2E `player_state` boot waits and manual QA
until a browser timing artifact writer is added.

## Known Limits

- RAG query timing is allowed to return a clean configuration/setup error when
  no embedding model or Qdrant collection is available in the local demo stack.
- These numbers target one DM plus a small local party, not hosted multiplayer
  scale.
