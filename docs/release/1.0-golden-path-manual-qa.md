# TableTop DM 1.0 Golden-Path Manual QA

Use this script on a fresh checkout or clean release artifact after the automated
E2E golden path passes. Record failures as release blockers unless a workaround
is explicitly documented in the RC notes.

## Preconditions

1. Start the Docker-backed local app:
   ```powershell
   .\scripts\verify_boot.ps1 -Mode docker
   .\scripts\start.ps1 -Mode docker
   ```
   If this is a disposable QA database and startup reports an already-applied
   migration checksum mismatch, rebuild the local Docker volumes and reseed:
   ```powershell
   .\scripts\start.ps1 -Mode docker -ResetDb
   ```
2. Open `http://localhost:8000/`.
3. Confirm `/health`, `/readyz?verbose=1`, `/`, `/game`, `/control`, and `/help`
   all load.

## DM Setup

1. Open Control Plane.
2. Create a new campaign named `V1 Manual QA <date>`.
3. Create a new session for that campaign.
4. In Players / Join, create one player principal.
5. Create a join code for that player and copy the generated `/game` link.
6. Create one PC assigned to that player.
7. Create one NPC or monster.
8. Add both entities to the active session.
9. Confirm the map hierarchy exists and the PC/NPC appear in the session party.

Expected:
- Campaign/session creation succeeds without manual database work.
- The player join link includes both `principal_id` and a join token.
- No player link exposes DM, God, NPC-agent, or other player identities.

## Player Playthrough

1. Open the copied player join link in a separate browser profile or private window.
2. Confirm `/game` loads from `player_state`.
3. Confirm the principal selector is hidden.
4. Confirm Start Encounter, Advance Initiative, and AI Narration are hidden.
5. Move the controlled PC on the map.
6. Discover or inspect a nearby POI.
7. Send a chat message.
8. Reload the page.

Expected:
- The same principal and controlled PC resume after reload.
- No DM-only text, `dm_only`, `dm_private_notes`, or hidden recap/source data appears.
- Movement and chat land in the event feed without duplicate rows.

## Combat And Save

1. As DM, switch the campaign to COMBAT.
2. Start an encounter.
3. As player, confirm the combat HUD appears only when the controlled PC is active.
4. Resolve one turn action or End Turn.
5. Export a game save with a passphrase.
6. Attempt to import the same save with `replace=false`.
7. Reload `/game`.

Expected:
- The import rejects cleanly as a conflict.
- The active session resumes.
- Player visibility remains scoped.
- No traceback or raw exception appears in the browser.

## Save/Load Torture Checks

Run these before a GA tag, preferably on a copied QA campaign:

1. Export a game save and a program save with a known passphrase.
2. Attempt imports with:
   - wrong passphrase,
   - truncated file,
   - non-`.ttdm` file,
   - corrupted header,
   - future schema version,
   - wrong save kind.
3. Confirm every failure returns a clean user-facing error, never a 500.
4. Import a game save with `replace=true` over an active session.
5. Confirm campaign state, sessions, maps, entities, ledger visibility, player state,
   RAG document metadata, RAG chunks, and embedding profiles survive restore.
6. Export a program save, move it to another install or clean VM, import it, and
   confirm principals remap by `auth_subject` and API keys are re-encrypted in
   the destination vault.

## Cleanup

1. Purge the QA campaign from Control Plane or via the API.
2. Stop the app:
   ```powershell
   .\scripts\stop.ps1 -Mode docker
   ```
