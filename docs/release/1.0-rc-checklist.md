# TableTop DM 1.0 RC Checklist

This checklist is the release-candidate gate for TableTop DM 1.0. It is deliberately narrower than the full roadmap: the goal is a playable, recoverable, visibility-safe local VTT, not every future feature.

## Release Rule

1.0 can ship only when there are no blocker or critical issues open against the core gameplay path.

Minor defects may ship only when they are documented in the release notes and do not affect boot, play, save/load, visibility, auth, or recovery.

## Severity Definitions

| Severity | Definition | Ship Status |
| --- | --- | --- |
| Blocker | Data leak, save corruption, cannot boot, cannot start a session, cannot load `/game`, or cannot recover from restart | Must fix |
| Critical | Broken golden path, broken player state, broken auth, broken import/export, broken WebSocket visibility, or broken DM review apply flow | Must fix |
| Major | Normal use is blocked or confusing enough that a DM cannot complete the core workflow without source-code knowledge | Fix or explicitly defer with owner |
| Minor | Polish, wording, layout, non-core edge case, or non-blocking UX friction | May ship if documented |
| Post-1.0 | RAG reranker, advanced chunk visibility UI polish, advanced economy/faction tuning, extra themes, marketplace/import ecosystem | Excluded from 1.0 gate |

## Required Automated Gate

Run these before tagging an RC:

```powershell
python -m py_compile app.py services/**/*.py shared/**/*.py
node --check static/js/app.js
pytest tests/services tests/contracts tests/integration -vv
pytest tests/e2e -rs -vv
```

When available, also run:

```powershell
pytest tests/e2e/test_v1_golden_path.py -vv
pytest tests/integration/test_route_auth_matrix.py -vv
pytest tests/integration/test_player_state_snapshot.py -vv
pytest tests/integration/test_socket_visibility.py -vv
pytest tests/integration/test_save_load_roundtrip.py -vv
```

## Manual Acceptance

| Check | Required Outcome | Status |
| --- | --- | --- |
| Fresh install | A clean checkout can boot through the documented path | Pending |
| Demo mode | A demo campaign can run without API keys | Pending |
| DM setup | A DM can create or load a campaign | Pending |
| Session lifecycle | A DM can create, pause, resume, end, and archive a session | Pending |
| Player join | A player can join through the supported local identity/join flow | Pending |
| Player state | `/game` loads from the principal-scoped player state snapshot | Pending |
| Movement | A controlled player character can move on a map | Pending |
| POI discovery | Nearby visible POIs appear; hidden/out-of-radius POIs do not | Pending |
| Combat | A basic combat loop can start, advance, resolve actions, and end | Pending |
| Chat/narration | Visible chat and narration appear only to allowed principals | Pending |
| DM visibility | The DM can see DM-only state and scoped player state views | Pending |
| Player visibility | Players cannot see DM-only, off-map, out-of-radius, or other-player-private state | Pending |
| Realtime reconnect | Disconnect/reconnect or reload does not widen state or duplicate events | Pending |
| Save/load | Export/import preserves state, principals, ledger visibility, and player state | Pending |
| Restart recovery | Server restart followed by resume returns a coherent visible state | Pending |
| DM packet review | Pending patches show evidence and can be approved, edited, or rejected | Pending |
| Readiness | `/health` and `/readyz?verbose=1` explain dependency state clearly | Pending |
| Docs | README and help docs match the shipped behavior | Pending |

## RC Burn-Down

Before cutting an RC:

1. Open a tracked issue for every failing gate.
2. Classify each issue with the severity table above.
3. Move non-core enhancements to post-1.0.
4. Re-run the automated gate after every blocker or critical fix.
5. Record final known limitations in the release notes.

## Packaging Gate

The release artifact must include:

| Artifact | Required Outcome |
| --- | --- |
| `release/TableTopDM-v1.0.0.zip` | User-facing package with app, scripts, docs, and examples |
| `release/checksums.txt` | Checksums for release artifacts |
| `release/README-FIRST.md` | First-run instructions, prerequisites, and troubleshooting entry points |
| `.env.example` | Complete local configuration template |
| Startup scripts | Windows shortcut/script and stop script verified |
| Docker path | Docker Compose dependencies boot cleanly |

## Performance Smoke Budgets

These are local demo targets, not enterprise benchmarks:

| Surface | Budget |
| --- | --- |
| `GET /api/sessions/<id>/player_state` | Under 300 ms on demo campaign |
| WebSocket event fanout | Under 150 ms local delivery |
| `/game` first usable render | Under 2 seconds after app readiness |
| RAG query | Under 1 second for demo documents |
| Save export/import | Under 5 seconds for demo campaign |
| Startup readiness | Under a documented, repeatable local budget |

## Exit Criteria

The 1.0 RC track is complete when:

- The automated gate passes.
- The manual acceptance checklist has no blocker or critical failures.
- The route/auth/visibility matrix has coverage for all exposed routes.
- Save/load has a passing torture suite.
- Snapshot and realtime delta behavior reconcile after reload and reconnect.
- Docs describe the app that actually ships.
- All known limitations are documented.
