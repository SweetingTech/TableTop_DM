# Player-history and control handoff verification

This report follows the [Section G checklist](../../AUTONOMOUS_CAMPAIGN_CHECKLIST.md#g-player-history-stand-ins-and-control-handoffs). The exact checked revisions and test output are in [the verification record](checks.txt).

| Criterion | Evidence |
| --- | --- |
| G1 | [Decision origins](https://github.com/SweetingTech/TableTop_DM/pull/121) classify server-derived manual input, advice, operator actions, stand-ins, and policy/model NPCs independently of execution authority. The [typed direction and trial test](../../../tests/integration/test_section_g_campaign.py#L143) commits a private director origin and a successful manual trial action. [Human evidence capture](../../../kernel/api/app.py#L773) uses the locked pre-action scene and source event. The speech tests retain classified intent, volume and cadence with the committed utterance's event ID. |
| G2 | The [choice profile](../../../cognition/choices.py#L208) compares matched human actions by the options that were offered. It records supporting events, confidence and per-option sample counts. [Assistance through the worker](../../../tests/integration/test_tactical_choices.py#L27) follows the player's demonstrated choice of healing a previous helper over self-healing. Movement, guard, target selection and speech regression tests exercise their specific comparable contexts. |
| G3 | [Persona and authored behavior](../../../tests/unit/kernel/test_speech_combat_behavior.py#L351) drive different no-history decisions. [The offered-choice regression](../../../tests/unit/kernel/test_tactical_choices.py#L237) verifies that a tactical option absent from the human examples keeps its fallback and that repeated choices among offered options change the scores. The private behavior and choice profile routes expose conflicts for card or history review. |
| G4 | [Trial and direction isolation](../../../tests/integration/test_section_g_campaign.py#L143) commits both actions and recreates the app. The canonical profile and exactly four original human-choice rows are preserved. Behavior readers match player, card, body, world, branch and run. A revised timeline collects its own training examples. |
| G5 | [The durable takeover test](../../../tests/integration/test_controller_runner.py#L345) races two workers for one logical turn and rejects a prepared stale action after a takeover. The [controller fence](../../../kernel/control.py#L65) applies the current epoch, step and execution actor to command commit. |
| G6 | [The console journey](../../../tests/e2e/test_controller_runner_isolated.py) opts into a 15-second disconnect timeout and actually leaves the page. It proves one bounded turn, visible pause policy, reconnect and takeover. [The durable timeout test](../../../tests/integration/test_controller_runner.py#L63) also verifies renewal with two minutes of app clock skew, restart and competing timeout workers. |
| G7 | [The mixed campaign test](../../../tests/integration/test_section_g_campaign.py#L42) joins the accepted command, committed event and private decision receipt. The dedicated execution actor is distinct from the player attributed in the behavior profile. [The grant test](../../../tests/integration/test_controller_runner.py#L405) checks world/body-scoped actor visibility and authority. |
| G8 | [The in-progress action test](../../../tests/integration/test_controller_runner.py#L183) proves takeover preserves the action wait and original receipt through retries. [The recap read](../../../kernel/api/app.py#L2585) waits for the window's frozen observations and renders the character's witnessed account. It leaves private epoch and revision markers out of the fiction. |
| G9 | [The campaign integration test](../../../tests/integration/test_section_g_campaign.py#L42) runs on isolated PostgreSQL with a real projector and worker. It starts with one human seat, adds a second character, then tests mixed and all-autonomous control on the same world and run. The first stand-in follows the recorded help preference. The history-free companion uses its peaceful backstory to de-escalate. The tests compare in-character context across handoffs and return control to the same body. |

The [player-history and speech tests](../../TESTING.md) can be rerun with the standard PostgreSQL integration environment. The focused campaign verification uses these lanes.

```powershell
$env:TTDM_INTEGRATION = '1'
uv run python -m pytest -v tests/integration/test_section_g_campaign.py tests/integration/test_tactical_choices.py tests/integration/test_controller_runner.py tests/integration/test_player_behavior.py tests/integration/test_speech_combat_behavior.py
uv run python -m pytest -v --browser chromium tests/e2e/test_controller_runner_isolated.py tests/e2e/test_player_behavior_isolated.py tests/e2e/test_speech_combat_behavior_isolated.py
```
